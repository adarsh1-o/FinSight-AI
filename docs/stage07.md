# Stage 07 — Fraud and Anomaly Validation

## Current status

Stage 07 adds reusable transaction validation, a repeatable scoring pipeline, a synthetic-label benchmark, bounded investigation APIs, and a Streamlit investigation tab. It preserves the FastAPI → data service → processed CSV structure. It is a local demonstration workflow, not a production fraud system.

## Actual dataset audit

The reproducible detailed audit is [stage07_dataset_audit.json](stage07_dataset_audit.json). It inspects raw and processed schemas, types, missing values, duplicates, amounts, timestamps, known categories, customer/account references, label coverage, and anomaly outputs.

At the audit run:

- Raw transactions: 100,050 rows and 10 columns; 50 exact duplicate rows / transaction IDs. No missing values, invalid amounts, or invalid timestamps were found. IDs and customer/account references were present and matched the corresponding raw entity files.
- The existing processed anomaly data has 100,000 rows, 25 columns, unique IDs, no missing values, and derived time/customer features plus Isolation Forest output.
- `fraud_labels.csv` contains 100,000 rows with a one-to-one ID match: 2,795 positive and 97,205 negative labels.
- Those labels are generated from randomized probabilities based on amount, location, transaction hour, merchant category, and status. They are synthetic heuristic labels, not independently confirmed fraud outcomes.
- Isolation Forest flags 5,000 of 100,000 processed transactions (5%). Its `-1` output maps to potential anomaly; `1` maps to normal. `isolation_score` is a ranking score, not a fraud probability.

## Benchmark methodology and result

`api.pipeline.evaluation.evaluate_anomalies` maps synthetic `is_fraud` false/true to 0/1 and Isolation Forest -1/1 to anomaly/normal 1/0. The label is not used for feature preparation or fitting. This is a descriptive comparison on the same synthetic transaction sample, not held-out validation, and the labels are generated by artificial heuristic rules.

| Metric | Synthetic benchmark |
|---|---:|
| Rows compared | 100,000 |
| Precision | 0.0332 |
| Recall / true-positive rate | 0.0594 |
| F1 | 0.0426 |
| False-positive rate | 0.0497 |
| True negatives / false positives | 92,371 / 4,834 |
| False negatives / true positives | 2,629 / 166 |

These numbers describe agreement with generated labels only. They do not establish real fraud detection quality.

## Pipeline

Run from the repository root:

```bash
python -m api.pipeline --input data/raw/transactions.csv --output data/processed/transactions_with_anomalies.csv --report data/processed/pipeline_summary.json --customers data/raw/customers.csv
```

The pipeline validates required fields and critical values, reports missing values and category/reference warnings, removes only exact duplicate rows, and fails if conflicting rows share an ID. It derives the notebook's existing time/customer-relative features and IQR flag, then applies the same StandardScaler + OneHotEncoder + Isolation Forest feature/model convention (100 estimators, contamination 0.05, seed 42). It atomically replaces the output CSV instead of appending, preserving raw input. Paths, seed, and contamination are configurable from the CLI. `python -m api.pipeline.audit` regenerates the repository dataset audit JSON.

## API and dashboard

- `GET /api/quality/summary` returns schema and quality findings, including label availability.
- `GET /api/anomalies/evaluation` returns the synthetic benchmark or an explicit unavailable status.
- `GET /api/investigations` supports pagination (maximum 500 rows), date and existing transaction filters, anomaly status, ID search, amount bounds, and score/date/amount sorting.
- `GET /api/investigations/export` downloads the matching filtered records as CSV, capped at 100,000 rows.

The dashboard's **Investigate** tab uses the API for filtered transaction context and CSV export. A displayed synthetic label is explicitly named `synthetic_fraud_label`; it must not be read as a verified review outcome. Existing dashboard filters apply, with local anomaly status, category, ID, and amount filters added.

## Run and verify

```bash
python -m api.pipeline.audit
python -m pytest api/tests/ -q
uvicorn api.main:app --reload
streamlit run dashboard/app.py
```

The static CSV architecture, synthetic generated labels, same-sample benchmark, fixed unsupervised contamination, and absence of a human review lifecycle remain limitations. A production evaluation requires independently adjudicated labels, time-separated holdout evaluation, calibration/threshold review, monitoring, access controls, and privacy review.
